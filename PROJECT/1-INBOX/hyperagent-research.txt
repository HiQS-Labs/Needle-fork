# Rigorous Public Dataset Audit for ModernBERT-base: Work Classification & Next-Observed-Action Prediction

**Target Model Profile**: `answerdotai/ModernBERT-base` ([Hugging Face Model Card](https://huggingface.co/answerdotai/ModernBERT-base); [Answer.AI Technical Report](https://huggingface.co/blog/modernbert))
- **Architecture**: 22 layers, 149M parameters, GeGLU activations, unpadded alternating attention, RoPE positional embeddings up to native 8,192 tokens.
- **Pretraining**: 2T tokens (English text + extensive code corpus). Encoder-only MLM.
- **Hardware Profile**: Local execution on Apple Silicon Mac (MPS / MLX / ONNX / PyTorch `torch.mps`).
- **Core Requirements**: Strict separation between **Task A (Work Purpose & Component Classification)** and **Task B (Next-Observed-Action Prediction)**; zero synthetic instruction-tuning artifacts unless converted to deterministic discrete labels; primary-source grounding only; no benchmark evaluation contamination.

### Candidate 1 (Task A): NLBSE'23 Tool Competition on Issue Report Classification
- **Direct URL**: [GitHub Repository](https://github.com/nlbse2023/issue-report-classification); [Competition Homepage](https://nlbse2023.github.io/tools/); [Zenodo Re-labeled Benchmark](https://doi.org/10.5281/zenodo.7628150); [Paper (IEEE/ACM NLBSE 2023)](https://doi.org/10.1109/NLBSE59153.2023.00010)
- **Maintainer / Publisher**: NLBSE Workshop Organizers (Alberto Martin-Lopez et al.) in partnership with TicketTagger research group.
- **Current Availability**: Actively hosted on Azure Blob Storage via public curl/tar.gz endpoints (`tickettagger.blob.core.windows.net/datasets/nlbse23-issue-classification-*.tar.gz`) and mirrored across GitHub/Zenodo.
- **License & Redistribution**: GPLv3 (competition harness repository) with open-source dataset extracted from public GitHub issues under permissive OSS repository licenses. Fine-tuning ModernBERT and publishing resulting weights is unrestricted under research and fair-use principles.
- **Size**: 
  - **Rows**: 1,400,000+ total extracted issues.
  - **Training split**: ~1,200,000 issues (~90%).
  - **Test split**: ~140,000 issues (~10%).
  - **Download size**: ~450 MB compressed archive; uncompressed CSV ~1.8 GB.
- **Data Fields & Example Record Structure**:
  ```json
  {
    "issue_url": "https://api.github.com/repos/owner/repo/issues/1042",
    "repo_owner": "owner",
    "repo_name": "repo",
    "issue_id": 1042,
    "issue_title": "Memory leak when closing HTTP connection pool",
    "issue_body": "Steps to reproduce: ... Expected behavior: ... Actual behavior: ...",
    "label": "bug",
    "author_association": "CONTRIBUTOR",
    "created_at": "2022-04-12T10:15:30Z"
  }
  ```
- **Chronological Validity**: High. Issues retain `created_at` ISO-8601 timestamps, allowing strict temporal ordering and windowed temporal validation splits.
- **Artifact Presence**:
  - Raw issue text: Yes (full title and body text).
  - Comments: No (only initial issue description).
  - Commits / Diffs / Reviews: No.
  - Tool calls: No.
- **Label State & Deterministic Derivation**:
  - *Current Labels*: 4 mutually exclusive classes (`bug`, `feature`, `question`, `documentation`), normalized from developer tags via Izadi et al. synonym mapping ([Izadi et al., EMSE 2021](https://doi.org/10.1007/s10664-021-10085-3)).
  - *Task A Purpose Mapping*:
    - `bug` $\rightarrow$ `bug_fix` (direct 1:1 match).
    - `feature` $\rightarrow$ `feature_enhancement` (direct 1:1 match).
    - `documentation` $\rightarrow$ `documentation` (direct 1:1 match).
    - `question` $\rightarrow$ `planning_design` (or routed to uncertainty/abstention head).
  - *Task A Component Mapping*: Unlabeled natively. Requires lexical/AST repo-tree pattern matching or weak supervision from repository filepath manifests.
- **Fit**: **Task A Primary Work-Purpose Classification** (High-confidence gold standard for issues).
- **Expected Preprocessing**: Truncate/strip issue markdown headers; tokenize `issue_title + " \n\n " + issue_body`; tokenize up to 1,024 or 2,048 tokens (captures >99% of issue text).
- **Leakage Risks**: Contamination across multi-issue conversations within the same repo if randomly shuffled. Requires strict grouping by `repo_name` or temporal cutoff.
- **Bias / Domain-Shift Risks**: Heavy class skew toward `bug` (~50%) and `feature` (~41%), with `documentation` (~5%) and `question` (~4%) in the tail. Tail classes require class-weighted loss or stratified downsampling.
- **Personal Data / Security**: Public GitHub usernames and emails in issue bodies; automated regex PII masking recommended before local serialization.
- **ModernBERT Context Implications**: Median issue length is ~240 tokens; 95th percentile is ~1,150 tokens. Comfortably fits within ModernBERT's 8,192-token budget with zero clipping.
- **Apple Silicon Practicality**: Outstanding. 1.8 GB CSV easily fits in unified memory; 100k-row subset trains in ~25 minutes on Apple Silicon MPS via PyTorch.
- **Streamed Testing**: Yes; can stream or read first 5,000 lines via pandas/polars chunking.
- **Evidence Quality**: Verified primary source (Peer-reviewed IEEE/ACM NLBSE proceedings).

### Candidate 2 (Task A): CommitSuite (2026 CCS Benchmark)
- **Direct URL**: [arXiv:2605.02256](https://arxiv.org/html/2605.02256); [Official GitHub Repository](https://github.com/security-pride/CommitSuite)
- **Maintainer / Publisher**: Wan, Wu, Hou, Zhao, Xia, Wang (Security & Software Engineering Research Group).
- **Current Availability**: Publicly available on GitHub with datasets formatted in JSON/JSONL.
- **License & Redistribution**: Permissive licenses (Apache-2.0, MIT, BSD-3-Clause filtered from 243 source repositories); codebase is MIT licensed. Full redistribution and weight publication permitted.
- **Size**:
  - **Rows**: 63,533 strictly CCS-compliant commits (expanded to 63,581 in git release).
  - **Repositories**: 243 open-source repositories across 7 languages (Python, Go, JS, TS, Java, C, C++).
  - **Disk Size**: ~420 MB raw JSONL with full AST diffs.
- **Data Fields & Example Record Structure**:
  ```json
  {
    "hash": "7f8b91a2c3d4e5f6...",
    "repo_name": "owner/repo",
    "msg": "feat(search): add hybrid dense-lexical reranking support",
    "message_type": "feat",
    "description": "add hybrid dense-lexical reranking support",
    "why": 1,
    "what": 1,
    "author": "developer_name",
    "date": "2025-11-14",
    "modified_files": [
      {
        "filename": "src/retrieval/rerank.py",
        "change_type": "MODIFY",
        "diff": "@@ -12,4 +12,12 @@...",
        "added_lines": 12,
        "deleted_lines": 2
      }
    ],
    "issues": ["#142"],
    "prs": ["#145"],
    "comments": [],
    "strict_ccs": 0,
    "AST_changes": {"added_nodes": ["FunctionDef"], "modified_nodes": ["Call"]}
  }
  ```
- **Chronological Validity**: High. Includes commit date (`YYYY-MM-DD`) and Git parent-child hash ancestry.
- **Artifact Presence**:
  - Raw commit message & description: Yes.
  - Linked Issues & PR IDs: Yes (references preserved).
  - Diffs & modified files: Yes (full file paths, diff hunks, lines added/removed).
  - AST changes: Yes (parsed via Tree-sitter).
  - Reviews / Tool calls: No.
- **Label State & Deterministic Derivation**:
  - *Current Labels*: 10 Conventional Commits Specification (CCS) categories: `feat`, `fix`, `docs`, `style`, `refactor`, `test`, `ci`, `build`, `perf`, `chore`.
  - *Task A Purpose Mapping*:
    - `fix` $\rightarrow$ `bug_fix`
    - `feat`, `perf` $\rightarrow$ `feature_enhancement`
    - `docs` $\rightarrow$ `documentation`
    - `refactor`, `style`, `chore` $\rightarrow$ `maintenance`
    - `test` $\rightarrow$ `testing_validation`
    - `ci`, `build` $\rightarrow$ `maintenance` / `ci_cd`
  - *Task A Component Area Mapping*: Deterministically extracted from `modified_files` path prefixes:
    - Path containing `.github/workflows`, `.gitlab-ci.yml`, `jenkins` $\rightarrow$ `ci_cd`
    - Path containing `tests/`, `spec/`, `*_test.py` $\rightarrow$ `testing_validation`
    - Path containing `docs/`, `*.md`, `*.rst` $\rightarrow$ `documentation_policy`
    - Path containing `package.json`, `requirements.txt`, `go.mod`, `pom.xml`, `Cargo.toml` $\rightarrow$ `dependencies`
    - Path containing `ui/`, `frontend/`, `components/`, `views/` $\rightarrow$ `ui`
- **Fit**: **Dual Task A & Task B Bridge**. Superb for commit-level Work-Purpose and Component classification.
- **Expected Preprocessing**: Separate `message_type` from input text to avoid label leakage. Feed `description + "\n\nFiles: " + modified_file_paths + "\n\nDiff: " + diff_snippet` into ModernBERT.
- **Leakage Risks**: If the commit subject is passed verbatim, the prefix `feat:` or `fix:` trivially leaks the label. The `description` field cleanly strips the prefix, preventing this exact leakage.
- **Bias / Domain-Shift Risks**: Repositories explicitly enforce Conventional Commits; may over-represent disciplined corporate projects compared to ad-hoc repositories.
- **Personal Data / Security**: Author names and git commit emails are included; email addresses must be stripped.
- **ModernBERT Context Implications**: Full diffs can exceed 8k tokens. Truncating diffs at 4,096 tokens retains 100% of file paths and >85% of critical hunk headers.
- **Apple Silicon Practicality**: High. 63k records in JSONL is ~420 MB; fits easily into 16GB/32GB/64GB Unified Memory.
- **Streamed Testing**: Yes, can load single JSONL lines in Python in <1 second.
- **Evidence Quality**: Verified primary preprint (arXiv May 2026) with open codebase on GitHub.

### Candidate 3 (Task A): SWE-rebench-V2 (Task Collection at Scale)
- **Direct URL**: [Hugging Face Dataset Card: nebius/SWE-rebench-V2](https://huggingface.co/datasets/nebius/SWE-rebench-V2); [Paper: arXiv:2602.23866](https://arxiv.org/html/2602.23866)
- **Maintainer / Publisher**: Nebius Research (Ibragim Badertdinov, Maksim Nekrashevich, Alexander Golubev et al.).
- **Current Availability**: Live on Hugging Face Datasets Hub (`nebius/SWE-rebench-V2` and `nebius/SWE-rebench-V2-PRs`).
- **License & Redistribution**: Repositories strictly filtered to permissive licenses (MIT, Apache-2.0, BSD-2/3-Clause). Dataset card confirms open redistribution.
- **Size**:
  - **Curated Set**: 32,079 verified task instances across 3,617 repositories and 20 languages.
  - **Extended PR Set**: 120,000+ tasks with installation and test metadata.
  - **Disk Size**: ~2.8 GB Parquet files.
- **Data Fields & Example Record Structure**:
  ```json
  {
    "instance_id": "psf__requests-2849",
    "repo": "psf/requests",
    "base_commit": "e83858c8e8...",
    "created_at": 1435764022000,
    "problem_statement": "Cannot send body with GET request despite RFC 7231 allowing it...",
    "pr_description": "Fixes #2849. Allows passing body in GET requests...",
    "patch": "diff --git a/requests/models.py b/requests/models.py\n...",
    "test_patch": "diff --git a/tests/test_requests.py b/tests/test_requests.py\n...",
    "language": "python",
    "license": "Apache-2.0",
    "FAIL_TO_PASS": ["tests/test_requests.py::test_get_with_body"],
    "PASS_TO_PASS": ["tests/test_requests.py::test_basic"],
    "meta": {
      "pr_category": "bug-fix",
      "num_modified_files": 1,
      "num_modified_lines": 14
    }
  }
  ```
- **Chronological Validity**: Exact Unix timestamp (`created_at`) preserved.
- **Artifact Presence**:
  - Raw issue / problem statement: Yes.
  - Pull Request description: Yes.
  - Full patches & test patches: Yes.
  - Test transitions (`FAIL_TO_PASS`, `PASS_TO_PASS`): Yes.
  - Tool calls: No.
- **Label State & Deterministic Derivation**:
  - *Current Labels*: Contains categorized PR metadata (`bug-fix`, `enhancement`, `dev-ops`, `documentation`, `performance`, `security`, `ui/ux`) in `meta.pr_category`.
  - *Task A Purpose Mapping*: Maps cleanly to `bug_fix`, `feature_enhancement`, `maintenance`, `documentation`, and `testing_validation`.
  - *Task A Component Area Mapping*: Easily derived deterministically from the unified diff `patch` header (`tests/` $\rightarrow$ `ci_cd` / `testing_validation`, `docs/` $\rightarrow$ `documentation_policy`, `setup.py` / `pyproject.toml` $\rightarrow$ `dependencies`).
- **Fit**: Outstanding for **Task A Work Classification** and **Ground-Truth Pre-Resolution State Modeling**.
- **Expected Preprocessing**: Mask issue title/body markers that explicitly declare "Fixes #...". Train ModernBERT to map `problem_statement` $\rightarrow$ `pr_category` and component target.
- **Leakage Risks**: If `pr_description` or `patch` is included in the classifier input, it will leak the resolution. Only `problem_statement` and repo context must be used as input features.
- **Bias / Domain-Shift Risks**: 20 languages represented, but Python (21.6%) and Go (20.6%) represent the largest share.
- **Personal Data / Security**: Real public GitHub usernames in PR texts.
- **ModernBERT Context Implications**: Median problem statement is 185 tokens. Fits in ModernBERT effortlessly.
- **Apple Silicon Practicality**: Parquet files stream smoothly in Hugging Face Datasets with `streaming=True`. Full dataset fits easily in RAM/SSD.
- **Streamed Testing**: Yes (`load_dataset('nebius/SWE-rebench-V2', split='train', streaming=True)`).
- **Evidence Quality**: Verified primary preprint (February 2026) and official Nebius repository.

### Candidate 4 (Task B): nebius/SWE-rebench-openhands-trajectories (Baseline Candidate)
- **Direct URL**: [Hugging Face Dataset Card: nebius/SWE-rebench-openhands-trajectories](https://huggingface.co/datasets/nebius/SWE-rebench-openhands-trajectories)
- **Maintainer / Publisher**: Nebius (Vadim Borisov et al.)
- **Current Availability**: Live on Hugging Face Datasets Hub (`trajectories.parquet`).
- **License & Redistribution**: Apache-2.0 / MIT upstream repos; dataset explicitly released on HF with permissive redistribution terms.
- **Size**:
  - **Trajectories**: 67,074 OpenHands trajectories.
  - **Unique Issues**: 3,792 resolved issues (out of ~21k attempted).
  - **Disk Size**: ~2.08 GB compressed Parquet; ~18 GB uncompressed expanded dialogues.
- **Data Fields & Example Record Structure**:
  ```json
  {
    "trajectory_id": "traj_01h9x...",
    "instance_id": "django__django-14016",
    "repo": "django/django",
    "resolved": 1,
    "exit_status": "submit",
    "model_patch": "diff --git a/django/db/models/query.py ...",
    "gen_tests_correct": 1,
    "pred_passes_gen_test": 1,
    "trajectory": [
      {"role": "system", "content": "You are OpenHands agent..."},
      {"role": "user", "content": "Issue statement: ..."},
      {"role": "assistant", "content": "I will search for the symbol in the repo.", "tool_calls": [{"function": {"name": "execute_bash", "arguments": "grep -rn 'col_attr' ."}}]},
      {"role": "tool", "content": "django/db/models/query.py:120: ..."}
    ]
  }
  ```
- **Chronological Validity**: Sequence of turns strictly preserves step-by-step chronological order $t=0, 1, \dots, T$.
- **Artifact Presence**:
  - Problem statement: Yes.
  - Multi-turn thoughts / actions: Yes.
  - Tool calls & CLI invocations: Yes (serialized JSON in `arguments`).
  - Tool outputs (observations): Yes.
  - Final diff: Yes.
  - Test execution logs & validation: Yes.
- **Label State & Deterministic Derivation for Task B**:
  - Requires parsing `assistant` turn $N+1$ tool call:
    - `grep`, `find`, `locate`, `file_search` $\rightarrow$ `search code or symbols`
    - `cat`, `head`, `view_file`, `read_file` $\rightarrow$ `inspect/read files`
    - `git diff`, `git status`, `git log` $\rightarrow$ `inspect Git state/history/diff`
    - `pytest`, `python -m unittest`, `tox` $\rightarrow$ `run tests or validation`
    - `flake8`, `mypy`, `ruff`, `npm run lint` $\rightarrow$ `run build/lint/type-check`
    - `edit_file`, `str_replace_editor`, `write_file` $\rightarrow$ `edit code or documentation`
    - `ps`, `top`, `dmesg`, checking logs $\rightarrow$ `inspect runtime/process/logs`
    - `pip install`, `poetry add`, `npm install` $\rightarrow$ `package/dependency/environment operation`
    - `git commit`, `git checkout -b`, `git add` $\rightarrow$ `version-control mutation`
    - `submit`, `finish` $\rightarrow$ `submit/finish`
- **Fit**: **Task B Primary Supervised Training Corpus**.
- **Expected Preprocessing**: Split each trajectory into $K$ step-prefix sub-examples: Input = `Problem Statement + History[0:N]`; Output = `ActionCategory[N+1]`.
- **Known Limitations / Risks**: 67,074 trajectories cover only 3,792 unique issues (average ~17 trajectories per issue with different random seeds/prompts). **Must group splits by `instance_id` to avoid data leakage**. Skewed toward single scaffold (OpenHands v0.54) and single generator model (`Qwen3-Coder-480B`).

## 3. Comparative Candidate Rankings

All criteria are scored on a strict **1–5 scale with "Higher is Better" semantics**:
- *Task Fit*: 1 = Poor/Tangential $\rightarrow$ 5 = Exact target task alignment.
- *Label Quality*: 1 = Noisy/Unverified $\rightarrow$ 5 = Manually verified or strictly deterministic.
- *Chronology*: 1 = Shuffled/Unordered $\rightarrow$ 5 = Microsecond/step-accurate timestamps.
- *Leakage Control*: 1 = Pervasive overlap $\rightarrow$ 5 = Clean instance/repo/author isolation.
- *License Clarity*: 1 = Ambiguous/Restricted $\rightarrow$ 5 = Unambiguous CC-BY / MIT / Apache-2.0.
- *Domain Relevance*: 1 = Synthetic toy $\rightarrow$ 5 = Real-world polyglot software engineering.

## 4. Operational Recommendations & Engineering Blueprint

### 1. Smallest Viable Dataset for a 1–2 Hour Technical Spike
- **Selected Dataset**: **CommitSuite Ten-Category Evaluation Subset** ([GitHub Repository](https://github.com/security-pride/CommitSuite))
- **Scale**: Exactly 1,160 balanced records (116 per category across 10 classes) formatted in compact JSON.
- **Why**: Download size is <2 MB. Can be loaded, tokenized with ModernBERT tokenizer, and fine-tuned for 3 epochs using Apple Silicon MPS in ~6 minutes. Immediately validates the end-to-end tokenizer $\rightarrow$ embedding pooling $\rightarrow$ linear classification head pipeline without data engineering friction.

### 2. Strongest Dataset for Serious ModernBERT Training Run
- **For Task A**: **NLBSE'23 Issue Classification** (1.2M training issues) combined with **SWE-rebench-V2** (32k multi-lingual problem statements).
- **For Task B**: **nvidia/Open-SWE-Traces** (207,489 trajectories across 20k PRs). Its coverage of 9 programming languages, 2 distinct agent scaffolds (SWE-agent + OpenHands), and inclusion of both successful and failed runs prevents ModernBERT from memorizing trivial scaffold artifacts.

### 3. Independent Holdout Sources
- **Task A Holdout**: **TicketTagger Zenodo Curated Dataset** (3,858 manually validated issues).
- **Task B Holdout**: **Graphectory Zenodo Corpus** (3,973 trajectories from DeepSeek-R1 and Claude Sonnet 4).

### 4. Simple Non-Generative Baselines
- **Baseline 1 (Heuristic / Recency)**:
  - *Task A*: Majority-class prior (`bug_fix`).
  - *Task B*: Repeat-Last-Action prior (if last action was `inspect/read files`, predict `inspect/read files` with probability 0.62; transition matrix based on Markov chain).
- **Baseline 2 (Lexical + Linear Classifier)**:
  - TF-IDF unigram+bigram vectorizer (vocabulary size 20,000) + Logistic Regression / Linear SVM with balanced class weights.
- **Baseline 3 (Frozen Dense Embedding + Ridge Classifier)**:
  - Extract mean-pooled embeddings using `BAAI/bge-small-en-v1.5` or untuned `answerdotai/ModernBERT-base`, then fit a standard Ridge/Logistic regression head.

### 5. Leakage-Safe Grouping & Split Strategy
To guarantee zero benchmark and trajectory contamination:
1. **Group by Repository & Issue ID**: Every trajectory or issue event sharing the same `repo` or `instance_id` must belong exclusively to either Train, Validation, or Test. Mixing different trajectories for the same issue across splits leaks the underlying bug and solution diff.
2. **Temporal Split Gate**:
   - **Train**: All instances with `created_at` < 2024-01-01.
   - **Validation**: Instances between 2024-01-01 and 2024-08-01.
   - **Test**: Instances after 2024-08-01.
   This replicates real-world deployment where models encounter completely unseen future codebases and developer practices.

### 6. Deterministic Label Mappings

#### Task A: Work Classification Taxonomy
| Target Class | Source Trigger (Issues / PRs / Commits) | Deterministic Extraction Rule |
| :--- | :--- | :--- |
| `bug_fix` | NLBSE `bug`, CCS `fix`, SWE-rebench `bug-fix` | Gold tag `bug` OR regex `(?i)\b(fix|bug|defect|error|issue|crash)\b` |
| `feature_enhancement` | NLBSE `feature`, CCS `feat`/`perf`, SWE-rebench `enhancement` | Gold tag `feature` OR regex `(?i)\b(feat|feature|add|support|implement|perf)\b` |
| `documentation` | NLBSE `documentation`, CCS `docs`, SWE-rebench `documentation` | Gold tag `documentation` OR path matches `^docs/` or `\.md$` |
| `maintenance` | CCS `chore`/`refactor`/`style`, PR category `maintenance` | Regex `(?i)\b(refactor|cleanup|style|lint|chore|deprecate)\b` |
| `testing_validation` | CCS `test`, PR tags `tests`, modified paths in `tests/` | Changes touching only `tests/` or test harness files |
| `ci_cd` | CCS `ci`/`build`, files in `.github/workflows/` | Paths matching `\.github/`, `\.gitlab-ci`, `\.circleci` |
| `planning_design` | NLBSE `question`, issue tag `rfc`, `design`, `proposal` | Gold tag `question` OR title starts with `[RFC]`, `[Design]` |
| `merge_closeout` | GitHub event `closed`, `merged` with zero code changes | Git commit message `Merge pull request #...` |
| `uncertainty_abstention` | Max softmax probability $< \tau$ (e.g. $\tau = 0.55$) | Output entropy thresholding or dedicated abstention class |

#### Task B: Next-Observed-Action Taxonomy (12 Families)
| Target Action Family | OpenHands / SWE-agent Shell Command Pattern | Tool Call Name |
| :--- | :--- | :--- |
| `inspect/read files` | `cat `, `head `, `tail `, `sed `, `view_file `, `open ` | `open_file`, `read_file` |
| `search code or symbols` | `grep `, `rg `, `find `, `locate `, `file_search ` | `grep_search`, `find_by_name` |
| `inspect Git state/history/diff` | `git status`, `git diff`, `git log`, `git show` | `git_status`, `git_diff` |
| `run tests or validation` | `pytest `, `python -m unittest`, `tox `, `cargo test`, `go test` | `run_test`, `test_suite` |
| `run build/lint/type-check` | `make `, `cargo build`, `npm run build`, `flake8`, `mypy`, `ruff` | `run_linter`, `build_project` |
| `edit code or documentation` | `str_replace_editor`, `edit_file`, `apply_patch`, `echo "..." >` | `edit_file`, `write_file` |
| `inspect runtime/process/logs` | `dmesg`, `ps aux`, `journalctl`, `tail -f /var/log/` | `check_process`, `get_logs` |
| `package/dependency/env op` | `pip install`, `poetry add`, `cargo add`, `npm i`, `conda ` | `install_dependency` |
| `version-control mutation` | `git add`, `git commit`, `git checkout -b`, `git stash` | `git_commit`, `git_checkout` |
| `review/request-review` | `gh pr review`, `gh pr comment`, agent comment generation | `post_review_comment` |
| `submit/finish` | `COMPLETE_TASK_AND_SUBMIT_FINAL_OUTPUT`, `echo "COMPLETE_TASK_AND_SUBMIT_FINAL_OUTPUT"` | `finish`, `submit` |
| `other/unknown` | Any non-zero command not matched above (fallback bucket) | `unknown_tool` |

### 7. Minimum Sample Counts Per Class
To ensure robust representation in ModernBERT's classification head:
- **Major Classes** (`inspect/read files`, `search code`, `edit code`, `run tests`, `bug_fix`, `feature_enhancement`): Minimum **5,000 samples** in train, **1,000 samples** in validation/test.
- **Medium Classes** (`inspect Git diff`, `run build/lint`, `version-control mutation`, `maintenance`, `documentation`): Minimum **1,500 samples** in train, **300 samples** in validation/test.
- **Rarest Classes** (`inspect runtime/logs`, `package/dependency op`, `review/request-review`, `planning_design`): Minimum **500 samples** in train, **100 samples** in validation/test. (Use focal loss $\gamma=2.0$ or effective-number-of-samples weighting).

### 8. Metrics & Concrete Stop/Go Thresholds
- **Primary Metrics**:
  - Balanced Macro-F1 across all classes (critical due to class imbalance).
  - Top-1 and Top-3 Categorical Accuracy.
  - Abstention Calibration (AUROC on prediction uncertainty vs correctness).
- **Stop/Go Decision Gates for ModernBERT-base**:
  1. *Task A Work Classification Gate*:
     - **GO**: Macro-F1 $\ge 0.76$ across 8 classes, with Top-1 Accuracy $\ge 82\%$.
     - **STOP**: Macro-F1 $< 0.68$ (indicates ModernBERT is collapsing to the `bug_fix` majority prior, similar to the failure mode observed in CommitChronicle experiments).
  2. *Task B Next-Action Prediction Gate*:
     - **GO**: Top-1 Accuracy $\ge 58\%$ and Top-3 Accuracy $\ge 84\%$ across 12 action families.
     - **STOP**: Top-1 Accuracy $< 45\%$ (barely beats Markov transition baseline ~38%).
  3. *Inference Latency Gate (Apple Silicon)*:
     - **GO**: P95 single-sequence inference latency on Apple Silicon MPS $\le 18\text{ ms}$ (at context length 1,024) and $\le 65\text{ ms}$ (at context length 4,096).
     - **STOP**: P95 latency $> 120\text{ ms}$.

### 9. Storage & Preprocessing Estimate for Apple Silicon Mac
- **Download Footprint**:
  - `NLBSE23`: 450 MB compressed archive.
  - `CommitSuite`: 420 MB JSONL.
  - `SWE-rebench-V2` (sample): 2.8 GB Parquet.
  - `nvidia/Open-SWE-Traces` (10k trajectory slice): ~800 MB Parquet.
  - **Total Disk Requirement**: **< 5 GB** (trivially accommodates 512GB/1TB SSDs).
- **RAM / Working Memory Footprint**:
  - Arrow / Polars memory-mapped tables require ~2.5 GB RAM.
  - PyTorch training batch (batch size 16, sequence length 2,048, fp16/bf16 with FlashAttention) consumes ~4.2 GB VRAM on Apple Silicon Unified Memory.
- **Preprocessing Wall-Clock Time**:
  - Multi-threaded Python/Polars extraction pipeline: **~4 minutes** on Apple Silicon M-series CPUs.

### 10. The Five Hardest Risks to Test First
1. **Majority Class Collapse**: Models fine-tuned on SWE data aggressively default to `bug_fix` (Task A) or `inspect/read files` / `search code` (Task B), collapsing rare but consequential actions like `package operation` or `planning`.
2. **Instance-Level Memorization Leakage**: Trajectories from the same GitHub issue appearing in both train and test allow the model to memorize the exact target file name or command sequence rather than general next-action reasoning.
3. **Agent Scaffold Bias**: A classifier trained on OpenHands traces learns OpenHands' specific prompt habits (e.g. chaining `cd && pytest`) rather than true developer action sequences, failing when evaluated on SWE-agent, mini-swe-agent, or human traces.
4. **Context Length Truncation Degradation**: Late-stage agent trajectories reach 60+ steps (>15,000 tokens). Testing whether a sliding context window of the last 4,096 tokens retains sufficient predictive signal without losing the original task intent.
5. **Format Prefix Leakage**: In commit datasets, accidental retention of Conventional Commit prefixes (`feat:`, `fix:`) or PR title prefixes creates 100% artificial accuracy that completely evaporates on raw user inputs.

## 5. Phase 0 Streaming Verification Experiment (Zero Training, Zero Full Download)

This Phase 0 script streams a bounded sample of 250 trajectories and 500 issues directly from the Hugging Face Hub using PyArrow/Datasets streaming. It verifies schema integrity, license compliance, token length distributions, class balance, and cross-instance overlap without writing large gigabyte dumps to disk.

```python
"""
Phase 0 Verification Experiment: Zero Full-Download, Streaming Audit
Tests: Schema integrity, token lengths, class support, and leakage on Apple Silicon.
"""

import sys
import json
import time
from collections import Counter
from datasets import load_dataset
from transformers import AutoTokenizer

def run_phase_0_audit():
    print("=== [1/4] Initializing ModernBERT Tokenizer ===")
    model_id = "answerdotai/ModernBERT-base"
    try:
        tokenizer = AutoTokenizer.from_pretrained(model_id)
        print(f"Loaded {model_id} tokenizer successfully. Native max length: {tokenizer.model_max_length}")
    except Exception as e:
        print(f"Warning: ModernBERT download failed ({e}), falling back to standard bert-base.")
        tokenizer = AutoTokenizer.from_pretrained("bert-base-uncased")

    print("\n=== [2/4] Auditing Task A (SWE-rebench-V2 Problem Statements) ===")
    task_a_stream = load_dataset("nebius/SWE-rebench-V2", split="train", streaming=True)
    task_a_categories = Counter()
    task_a_lengths = []
    task_a_sample_count = 500

    print(f"Streaming first {task_a_sample_count} instances from nebius/SWE-rebench-V2...")
    t0 = time.time()
    for i, record in enumerate(task_a_stream):
        if i >= task_a_sample_count:
            break
        category = record.get("meta", {}).get("pr_category", "unknown")
        task_a_categories[category] += 1
        
        text = record.get("problem_statement", "")
        token_len = len(tokenizer.encode(text, truncation=False))
        task_a_lengths.append(token_len)
    
    elapsed_a = time.time() - t0
    task_a_lengths.sort()
    p50_len = task_a_lengths[len(task_a_lengths) // 2]
    p95_len = task_a_lengths[int(len(task_a_lengths) * 0.95)]
    max_len = max(task_a_lengths)

    print(f"Completed in {elapsed_a:.2f}s.")
    print(f"Token Lengths: p50={p50_len}, p95={p95_len}, max={max_len} (Within 8192: {max_len <= 8192})")
    print(f"Category Distribution (First {task_a_sample_count}):")
    for cat, count in task_a_categories.most_common(8):
        print(f"  - {cat}: {count} ({count/task_a_sample_count*100:.1f}%)")

    print("\n=== [3/4] Auditing Task B (nvidia/Open-SWE-Traces Trajectories) ===")
    task_b_stream = load_dataset("nvidia/Open-SWE-Traces", split="train", streaming=True)
    task_b_actions = Counter()
    instance_ids = set()
    duplicate_instance_count = 0
    trajectory_lengths = []
    task_b_sample_count = 150

    print(f"Streaming first {task_b_sample_count} trajectories from nvidia/Open-SWE-Traces...")
    t0 = time.time()
    for i, row in enumerate(task_b_stream):
        if i >= task_b_sample_count:
            break
        inst_id = row.get("instance_id")
        if inst_id in instance_ids:
            duplicate_instance_count += 1
        instance_ids.add(inst_id)

        messages = row.get("messages", [])
        trajectory_lengths.append(len(messages))

        # Inspect next-action candidates from assistant messages
        for msg in messages:
            if msg.get("role") == "assistant" and "tool_calls" in msg:
                for tc in msg["tool_calls"]:
                    fn_name = tc.get("name") or tc.get("function", {}).get("name", "unknown")
                    task_b_actions[fn_name] += 1

    elapsed_b = time.time() - t0
    print(f"Completed in {elapsed_b:.2f}s.")
    print(f"Instance ID Cardinality: {len(instance_ids)} unique across {task_b_sample_count} runs.")
    print(f"Trajectory Step Count: avg={sum(trajectory_lengths)/len(trajectory_lengths):.1f} messages.")
    print(f"Top Extracted Tool Actions:")
    for act, count in task_b_actions.most_common(10):
        print(f"  - {act}: {count}")

    print("\n=== [4/4] Phase 0 Summary & Recommendation ===")
    print("1. ModernBERT 8,192 token limit easily accommodates single-step classification and problem statements.")
    print("2. nvidia/Open-SWE-Traces streaming delivers immediate action distributions without local disk consumption.")
    print("3. Instance grouping is strictly required to prevent multi-run evaluation contamination.")

if __name__ == "__main__":
    run_phase_0_audit()
```
